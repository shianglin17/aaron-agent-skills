# 成本估算

步驟 4 用。順序固定：使用量假設 → 單價 → 腳本計算 → 三情境 → 對照預算。

## 1. 先寫使用量假設

每個會計費的維度都要有一個數字和出處（使用者給的、從使用者給的數字推算、預設值）。

| 維度 | 低 | 可能 | 高 | 出處 |
|---|---|---|---|---|
| 每月請求數 | | | | |
| 平均回應大小（KB） | | | | |
| 對外流量（GB／月） | | | | |
| 運算時數或 vCPU‧秒 | | | | |
| 資料庫規格與儲存（GB） | | | | |
| 物件儲存（GB）與請求數 | | | | |
| 日誌量（GB／月） | | | | |
| （Cloudflare）每次請求的 CPU 毫秒、D1 每月讀寫列數、KV／R2／Queues 操作次數 | | | | |

- MAU 換算請求數要寫出換算方式，例如「每位 MAU 每月 20 次造訪 × 每次 30 個請求」。換算係數是假設，標出來。
- 三個情境只改使用量，不改架構。架構不同就是不同候選。

## 2. 單價只用官方來源

- 來源照 [verification.md](verification.md) 的〈價格來源〉。
- 每個單價記：服務、計費單位、區域、方案（隨需、承諾、Spot）、USD 單價、來源 URL、查詢日期。
- 查不到的單價：該項標「未驗證」，總額也標「含未驗證項目」。不要用其他區域的價格頂替，除非明寫「以 ○○ 區域代替，推論」。
- 階梯計價（越用越便宜）照實際級距算，不要取平均。

## 3. 算術一律用腳本

不心算、不在文字裡加總。用 `python3` 寫一個腳本，假設與單價放在最上面，報告附上完整腳本：

```python
# 單價：區域、USD、來源 URL、查詢日期寫在註解
PRICES = {
    "db_instance_hour": 0.0,   # 未驗證／或 URL + 日期
    "egress_gb": 0.0,
}
HOURS_PER_MONTH = 730  # 雲端價格頁常用的月時數，以價格頁寫的為準

SCENARIOS = {
    "低":   {"egress_gb": 0, "db_hours": HOURS_PER_MONTH},
    "可能": {"egress_gb": 0, "db_hours": HOURS_PER_MONTH},
    "高":   {"egress_gb": 0, "db_hours": HOURS_PER_MONTH},
}

def monthly(s):
    items = {
        "資料庫": s["db_hours"] * PRICES["db_instance_hour"],
        "對外流量": s["egress_gb"] * PRICES["egress_gb"],
    }
    return items, sum(items.values())

for name, s in SCENARIOS.items():
    items, total = monthly(s)
    print(name, {k: round(v, 2) for k, v in items.items()}, "合計", round(total, 2))
```

免費額度、credits、承諾折扣另外算一行「扣除後」，原價必須先列。

## 4. 常漏的費用

每個候選逐項檢查，不適用的寫「不適用」，不要直接略過：

- [ ] 對外流量（egress）：到網際網路、到 CDN、跨區域
- [ ] NAT：每小時費用加每 GB 處理費
- [ ] 跨可用區流量：多可用區部署、資料庫複本
- [ ] 負載平衡器：每小時最低費用，即使沒有流量
- [ ] 公有 IP 位址：是否單獨計費
- [ ] 日誌與監控：寫入量、保存期、自訂指標
- [ ] 資料庫：多可用區或高可用的加倍費用、備份儲存、快照
- [ ] 儲存：請求次數、取回費用、最短保存期
- [ ] 密鑰與憑證管理
- [ ] DNS 託管與查詢
- [ ] 容器映像儲存
- [ ] 寄信服務
- [ ] 技術支援方案
- [ ] 免費額度到期後的價格

**Cloudflare 特有的常漏項目**（只在候選含 Cloudflare 時檢查）：

- [ ] 帳號層級的月費底價（Workers Paid）：整個帳號只算一次，不要每個專案各算一次
- [ ] 免費額度的單位：有些是每日、有些是每月，換算成同一個月再比
- [ ] 請求數的計法：Workers 靜態資源請求、快取命中、service binding、WebSocket 連線是否計入，照 Workers 價格頁的腳註
- [ ] CPU 時間：等待網路與資料庫的時間不計入，但要用實際 CPU 毫秒估，不要用牆鐘時間
- [ ] D1：以列讀取、列寫入、儲存計費；每個查詢實際計入的列數，照價格頁的定義估
- [ ] R2：Class A、Class B 操作費、Infrequent Access 的資料取回費；Standard 的出站流量免費，但接到其他計費服務仍可能產生費用
- [ ] Durable Objects：請求、持續時間、儲存操作分開計；WebSocket 長連線的持續時間
- [ ] Queues、Workflows、KV：各自的操作次數（讀、寫、刪、列）
- [ ] Workers Logs、Logpush：日誌量與保存期的費用
- [ ] Containers、Workers AI、Vectorize 等：依各自價格頁的單位（vCPU 時間、神經元、向量維度）
- [ ] 其他需要付費方案的功能：自訂網域的企業功能、Data Localization Suite（企業方案附加功能）、Cache Reserve 等，確認候選用到的功能在哪個方案
- [ ] 出站流量：Workers、R2、D1 價格頁寫明不收；Containers 的出站流量要收費，且依地區分價（含台灣），不可套用「Cloudflare 不收出站流量」

以上每項的計法與單價都要照價格頁查證；Cloudflare 沒有官方計算機，用價格頁的計算範例核對公式。

## 5. 三情境與預算

輸出這張表，金額來自腳本輸出：

| 項目 | 低 | 可能 | 高 |
|---|---|---|---|
| （逐項） | | | |
| 合計（USD／月） | | | |
| 對照預算上限 | 未超過／超過 | | |

- 「可能」情境超過預算：在報告結論明講，並提出降本選項（降規格、改架構、承諾折扣），各自的代價也要寫。
- 只有「高」情境超過：寫成風險，說明觸發條件（例如「月流量超過 ○○ GB」）。
- 報告附一句：「實際費用以帳單為準，建議用官方計算機核對」，並附計算機連結。
