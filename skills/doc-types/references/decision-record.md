# 決策紀錄

專案 repo 的 `docs/adr/` 和個人或跨專案的決策紀錄庫，都用這份模板。

## 值不值得記

兩項都符合才記：

1. 明確選了 A、沒選 B。「沒有人反對」不算選。
2. 影響後續，而且改回來代價高。符合任一項：
   - 要動到兩個以上的模組。
   - 要遷移資料。
   - 要花錢。
   - 已經對外承諾。

不記：

- 隨時能改回的小選擇、文案、實作細節。寫在 commit 訊息。
- 延後做、只影響單一版本範圍的事。寫在 issue。
- 還沒做的決定。寫成方案頁。

## 誰寫、什麼時候寫

- 做決定的那個 session 或人，當場寫。不留到隔天從對話補寫。
- 專案內的決定：寫進該專案 repo 的 `docs/adr/`。
- 跨專案或個人方向的決定：寫進個人的決策紀錄庫。
- 只增不改。推翻時新增一則，寫「取代 NNNN」；舊的只改狀態為「已被取代」，內文不動。
- 編號循序，不重用。

## 模板

檔名：`NNNN-<英文短 slug>.md`。

```markdown
# NNNN 標題：寫成決定本身，例如「訊息佇列用 X」

| 欄位 | 內容 |
|---|---|
| 狀態 | 提議／採用／已被取代，見 [NNNN](NNNN-xxx.md) |
| 日期 | YYYY-MM-DD |
| 決定者 | 誰做的決定 |

## 背景

- 要解決什麼問題。
- 有哪些限制：時間、錢、相容性、規範。
- 術語第一次出現就解釋。

## 考慮過的選項

| 選項 | 結果 |
|---|---|
| 選項 A | 採用 |
| 選項 B | 不採用：一句理由 |

- 沒有比較過其他選項：寫「沒有比較其他選項」。不要湊數。

## 決定

- 一條一件事，用陳述句。

## 取捨與後果

**得到**

- ＿＿

**付出**

- ＿＿（不能空白）

**之後要注意**

- ＿＿

## 信心程度

高／中／低：一句依據。還沒驗證的部分寫出來。

## 何時重新檢討

- 日期，或觸發條件，例如「每日流量超過 X」「上游停止維護」。

## 相關

- issue、commit、其他決策紀錄、量測結果的連結。
```

## 寫法

- 一則只記一個決定。
- 只增不改，見〈誰寫、什麼時候寫〉。
- 短、肯定、只寫事實。
- 只寫結果與理由，不寫討論經過。
- 選項的理由寫成一句；細節放連結。

## 自查

- [ ] 符合〈值不值得記〉的兩項。
- [ ] 標題是決定本身，不是問題。
- [ ] 「付出」不是空白。
- [ ] 選項沒比較過時，寫了「沒有比較其他選項」。
- [ ] 信心程度寫了依據。
- [ ] 重新檢討有日期或觸發條件。
- [ ] 沒有設計細節或規格；那些放進文件，從這裡連過去。
