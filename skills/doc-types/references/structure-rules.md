# 結構規則

適用：頁面、artifact、超過一屏的文件。寫的時候照〈規則〉，寫完照〈檢查表〉逐條打勾。

## 規則

### 第一屏

- 狀況報告、方案頁照這節。其他類型的第一屏放一句結論，接著照 [types.md](types.md) 的骨架。
- 只放三樣：
  1. 一句結論。方案頁的結論是「要決定的問題＋建議選哪個＋一句理由」。
  2. 要讀者做的事。只列還要做的；已完成、已作廢的不列，也不留刪除線。
  3. 還沒解決的風險。
- 要讀者做的事寫清楚：做什麼、什麼時候前、怎麼回覆。
- 沒有要讀者做的事、也沒有風險：寫「不用處理」。
- 背景、方法、明細都往後放。
- 第一屏不放圖、表、數字摘要、狀態標記。

### 篇幅

- 動筆前定字數預算：整份多少字、每節多少字。驗收題答得出就停。
- 超過預算：細節收進可收合的區塊，或拆成另一份再連過去。

### 強調

- 字多時，依序處理：先刪字，再把結論放句首，再加標題或條列。這三步做完還要強調，才標重點。
- 標重點用粗體。一節最多一處，只標詞或短語，不標整句。
- 不用文字顏色或底色標重點。

### 章節順序

- 照讀者的問題排，不照做事的順序或資料來源排。
- 標題寫答案或讀者的問題：「退款五到七天入帳」，不寫「退款相關說明」。狀況報告的 `h1` 寫結論句，不寫主題名。
- 要行動或有風險的項目放前面；正常的合併成一行，或收合。
- 狀態項照「要不要讀者處理」分組：要處理的逐項寫，不用處理的合成一節，每組一行，不逐項加狀態標記。

| 不好：照做事的順序 | 好：照讀者的問題 |
|---|---|
| 第一週做了什麼 | 現在能用了嗎？ |
| 第二週遇到的問題 | 哪裡還有風險？ |
| 最後的結果 | 要你決定什麼？ |

### 寫給沒參與的人

- 讀者當作沒參與過這件事的人。用讀者認得的說法，不用系統內部的名字。
- 內部編號（ADR 0037、PR #59、issue #12、commit hash）不當主詞，也不單獨出現。先用一句白話說是什麼，編號放句尾括號或連結。
- 每一項先寫「對讀者的意思」（要做什麼、會發生什麼），再寫細節。
- 術語第一次出現時用一句話說明；能換成常用詞就換。
- 刪掉讀者用不到的：過程（見〈不放過程〉）、計數方式、給稽核看的說明。需要留的放明細區或收合區，不放正文。合併項目的總數仍要能從明細加總。

| 不好 | 好 |
|---|---|
| ADR 0037 已採用 | 訂單改用佇列處理，高峰期不再逾時（ADR 0037） |
| 合併 4 個 plugin 算 1 項，共 7 項 | 共 7 項；計數方式見明細 |

### 同一層的項目

- 互不重疊、合起來沒有遺漏、屬於同一類。
- 欄位相同：每個選項都有「做法、好處、代價」，每個狀態項都有「狀態、負責人、期限」。

### 不放過程

- 不寫試錯、討論經過、時間線。
- 需要時連到 issue、決策紀錄或紀錄檔。
- 例外：「試過不行的」可以一節，每項一句加連結。

### 一個事實只出現一次

- 同一個事實的明細只寫在最主要的那一處；其他地方連過去。
- 第一屏的摘要不算重複；但摘要跟明細的說法與數字要一致。
- 除了第一屏的摘要，其他地方只放連結或「見〈某節〉」，不重寫一次。例如同一個風險：第一屏一句摘要，明細寫一次，其他表只寫「見〈風險〉」。
- 方案頁的選項並排表，每個選項各寫自己的好處與代價，不算重複。
- 摘要的數字要能從明細加總。寫完自己加一次。
- 數字附出處與日期；沒量過寫「沒有紀錄」。

### 狀態用語

- 內容有狀態項時才用；沒有狀態項（例如方案頁、解釋）就略過這節與檢查表那一條。
- 動筆前定好：一個維度、最多 5 個值。
- 先寫出這個維度在問的問題，例如「原文還在嗎？」。每個值都必須是這個問題的答案，例如「在／已移除／查不到」。
- 全份只用這組詞。不混用不同維度，例如同一欄同時出現「緊急」和「已完成」。
- 第一次出現時說明每個值的意思。

### 其他類型的內容

- 不屬於這份類型的內容：放連結，或收進可收合的區塊。
- 必讀的內容不放在收合區或附錄。

## 檢查表

```
結構檢查：
- [ ] 第一屏只有結論、要讀者做的事、風險（狀況報告、方案頁）
- [ ] 第一屏沒有已完成、已作廢的項目；改版後重數過要讀者看的事
- [ ] 沒有超過字數預算
- [ ] 強調：先刪字、結論放句首、加標題或條列；粗體每節最多一處，只標詞或短語；沒有用文字顏色或底色
- [ ] 每個驗收題的答案找得到，說得出在哪一節
- [ ] 章節照讀者的問題排
- [ ] 同一層的項目不重疊、同一類、欄位相同
- [ ] 正文沒有過程；過程有連結
- [ ] 同一個事實只出現一次
- [ ] 摘要數字從明細加總得到
- [ ] 重複出現的事實，除了第一屏，其他地方只放連結
- [ ] 合併項目的總數加得起來；計數方式與稽核說明不在正文
- [ ] 狀態用語只有一個維度，每個值都回答同一個問題，不超過 5 個值（沒有狀態項就略過）
- [ ] 沒參與的人讀得懂：編號不當主詞、每項先寫對讀者的意思、術語第一次出現有說明；挑 3 個讀者可能看不懂的詞或編號，都處理了
- [ ] 要行動或有風險的項目在前面
- [ ] 現況與計畫分開
```
