# 結構規則

適用：頁面、artifact、超過一屏的文件。寫的時候照〈規則〉，寫完照〈檢查表〉逐條打勾。

## 規則

### 第一屏

- 只放三樣：
  1. 一句結論。方案頁的結論是「要決定的問題＋建議選哪個＋一句理由」。
  2. 要讀者做的事。
  3. 還沒解決的風險。
- 要讀者做的事寫清楚：做什麼、什麼時候前、怎麼回覆。
- 沒有要讀者做的事、也沒有風險：寫「不用處理」。
- 背景、方法、明細都往後放。

### 章節順序

- 照讀者的問題排，不照做事的順序或資料來源排。
- 標題寫答案或讀者的問題：「退款五到七天入帳」，不寫「退款相關說明」。
- 要行動或有風險的項目放前面；正常的合併成一行，或收合。

| 不好：照做事的順序 | 好：照讀者的問題 |
|---|---|
| 第一週做了什麼 | 現在能用了嗎？ |
| 第二週遇到的問題 | 哪裡還有風險？ |
| 最後的結果 | 要你決定什麼？ |

### 同一層的項目

- 互不重疊、合起來沒有遺漏、屬於同一類。
- 欄位相同：每個選項都有「做法、好處、代價」，每個狀態項都有「狀態、負責人、期限」。

### 不放過程

- 不寫試錯、討論經過、時間線。
- 需要時連到 issue、決策紀錄或紀錄檔。
- 例外：「試過不行的」可以一節，每項一句加連結。

### 一個事實只出現一次

- 同一個事實的明細只寫在最主要的那一處；其他地方連過去。
- 第一屏的摘要不算重複；但摘要跟明細的說法與數字要一致。
- 方案頁的選項並排表，每個選項各寫自己的好處與代價，不算重複。
- 摘要的數字要能從明細加總。寫完自己加一次。
- 數字附出處與日期；沒量過寫「沒有紀錄」。

### 狀態用語

- 內容有狀態項時才用；沒有狀態項（例如方案頁、解釋）就略過這節與檢查表那一條。
- 動筆前定好：一個維度、最多 5 個值，例如「要處理／進行中／完成」。
- 全份只用這組詞。不混用不同維度，例如同一欄同時出現「緊急」和「已完成」。
- 第一次出現時說明每個值的意思。

### 其他類型的內容

- 不屬於這份類型的內容：放連結，或收進可收合的區塊。
- 必讀的內容不放在收合區或附錄。

## 檢查表

```
結構檢查：
- [ ] 第一屏只有結論、要讀者做的事、風險
- [ ] 每個驗收題的答案找得到，說得出在哪一節
- [ ] 章節照讀者的問題排
- [ ] 同一層的項目不重疊、同一類、欄位相同
- [ ] 正文沒有過程；過程有連結
- [ ] 同一個事實只出現一次
- [ ] 摘要數字從明細加總得到
- [ ] 狀態用語只有一個維度，不超過 5 個值（沒有狀態項就略過）
- [ ] 要行動或有風險的項目在前面
- [ ] 現況與計畫分開
```
