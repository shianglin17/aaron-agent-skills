# 發布前審查

派一個審查者，只看得到成品。它不知道你怎麼做出來的，所以讀到的跟真正的讀者一樣。

## 給審查者什麼

| 給 | 不給 |
|---|---|
| 成品：檔案、或頁面渲染後的文字 | 對話、草稿、你的筆記 |
| 成品是頁面時：渲染後的畫面 | 製作時的說明或自評 |
| 讀者與任務那一句話 | 你對成品的說明或自評 |
| 驗收題 | 驗收題的答案 |

- 審查者是另一個 agent 時，開一個新的，不要沿用做這份東西的那一個。
- 沒辦法另派 agent：請使用者找人讀。都做不到時，自己只讀渲染後的成品回答驗收題，並在交付時說明「沒有獨立審查，只有作者自查」。

## 指示範本

```text
你是這份東西的讀者：<讀者與任務那一句話>。
只讀附上的成品，不要找其他資料。

1. 回答每一題驗收題。每題附答案的出處：章節標題或第幾段。
   答不出的題，寫「答不出」和你找過哪裡。
2. 只看第一屏，說出：結論是什麼、要你做什麼、有什麼風險。
3. 數第一屏要你做的事有幾件；列出第一屏裡已完成或已作廢的項目。不到 5 件事卻做成頁面，也寫出來。
4. 列出讀起來卡住的地方：看不懂的詞、要往回翻的地方、順序奇怪的章節。
5. 列出對不上的地方：同一件事說法不同、摘要數字跟明細加不起來、狀態用語混用。
6. 挑 3 個你看不懂的詞或編號，寫出來。
7. 有畫面時，看第一個視窗：看得到結論與要你做的事嗎？
8. 不要改寫成品，只回報。

驗收題：
1. <題目>
2. <題目>
3. <題目>
```

## 回來之後

- 答不出的題：改成品，不改題目。
- 第一屏說不出結論或要做的事：先改第一屏。
- 卡住和對不上的地方：逐條修。
- 「看不懂的詞或編號」：照 structure-rules.md〈寫給沒參與的人〉修。步驟 1 的讀者明確是內行、決定不改的，交付時寫明沒改什麼、為什麼。
- 修一輪後發布。改動大時，再派一個新的審查者看一次。
