# 頁面設計

成品是頁面（HTML、artifact）時，步驟 6 照這份。起點：[assets/skeleton/](../assets/skeleton/)。頁面規格照 `artifact-design`；修飾照 `impeccable`。

## 哪些內容做成圖

| 內容 | 做成 | 交給 |
|---|---|---|
| 3 步以上有先後，或有任一個分支 | 流程圖 | `diagram-design` |
| 3 個以上的東西彼此連接 | 架構圖或結構圖 | `diagram-design` |
| 狀態隨事件改變 | 狀態圖 | `diagram-design` |
| 同一個量跨時間，或跨 3 個以上類別比較 | 長條或折線 | `dataviz` |
| 部分占整體 | 堆疊長條 | `dataviz` |
| 只是列舉，項目之間沒有連接 | 清單 | 不畫 |
| 每項欄位相同，要逐格對照 | 表格 | 不畫 |
| 2 個以內的數字 | 句子 | 不畫 |

- 一張圖回答一個問題；圖前的 `h2` 寫那個問題。圖不取代文字結論。圖放進 `.fig`；SVG 要有 `<title>`、`<desc>`。

## 每種類型用哪些元件

每種類型都用 `.masthead`（`h1`＋`.sub`）開頭、`.foot` 結尾。

| 類型 | 元件 |
|---|---|
| 狀況報告 | `.act`（要讀者做的事）、`.items`＋`.kv`（要處理的項目明細）、`.groups`（不用處理的項目）、`.tbl.num`＋`.legend`（數字明細） |
| 方案頁 | `.act`（選哪個、期限、怎麼回覆）、`.options`（建議的選項加 `.rec`，標題後加 `.rec-mark`）、`.basis`、`details.more`（明細） |
| 決策紀錄 | `.kv`（狀態、日期、決定者）、`.tbl`（考慮過的選項）、`ul`（得到、付出） |
| 解釋 | `.fig`（主圖）、`ul`、`details.more` |
| 教學、操作指南 | `ol.steps`（編號步驟）、`.output`（會看到的結果）、`ul.checks`（確認做完）、`details.more`（常見問題） |
| 參考 | `.tbl.stack.fields`（一列一個欄位：名稱、型別、預設、說明）、`details.more` |

## 第一屏

- 狀況報告、方案頁依序：`.masthead` → `.act` → 風險。
- `h1` 寫結論句，是整頁最大的字。不寫主題名。
- `.sub` 寫日期與資料截至日期。方案頁的信心程度寫在 `h1` 或 `.sub`。
- `.act` 只有 1 件事：`h2` 直接寫那件事，下面用 `p` 寫怎麼做、不做會怎樣（`.why`）、怎麼回覆。不編號。
- `.act` 有 2 件以上：`h2` 寫件數，用 `ol` 的一般數字。
- 沒有要讀者做的事：`.act` 的 `h2` 寫「不用你處理」。
- 風險用一般文字，不加框、不加底色：`h2`＋`p`。2 項以上用 `ol`，正文才能寫「風險 2」回指。沒有風險：拿掉這節。
- 第一屏不放圖、表、數字摘要、狀態標記。
- 其他類型：`h1` 照 [types.md](types.md) 的骨架寫；`.masthead` 裡 `h1` 下面接一句結論（`p`），再照骨架。

## 版面硬規則

### 底色與框線

- 整頁只有一個底色 `--bg`。不用「灰底＋白卡」。
- 底色塊只有兩種：`.act`、`.option.rec`。都用 `--accent-tint`。
- 框線只用在 `.tbl` 與 `.fig`。其他元件用留白、字重、底色塊分開。
- 圓角只有兩種：底色塊 4px，表格與圖 6px。

### 字

- 只用一個字族 `--f-body`：系統的黑體（蘋方、思源黑體、微軟正黑體）。不載入網路字型。
- 檔名、指令、欄位名、程式輸出用 `--f-mono`，不加底色。
- 字級只有 4 層：

| 層 | 大小 | 用在 |
|---|---|---|
| `h1` | 32–48px | 結論句；整頁最大 |
| `h2` | 22px | 每節的問題、`.act` 的那件事 |
| 內文 | 17px | 正文；`h3` 是粗體的內文 |
| 輔助 | 15px | `.sub`、`.note`、`.meta`、表格、`.kv` 與 `.groups` 的標籤、`.foot` |

- 字重只用 400 與 700。
- 圖裡的字不算在字級裡。

### 顏色

- 強調色只有 `--accent` 一組（`--accent`、`--accent-ink`、`--accent-tint`）。只用在連結、`.act`、`.option.rec`、`details.more` 的標題、焦點框。
- 狀態色（`--ok`、`--warn`、`--bad`、`--unk`）只用在 `.st` 與 `.dot` 的圓點、`.checks` 的勾。圓點旁邊一定有狀態詞。
- 其他文字用 `--ink`、`--ink-2`、`--muted`。

### 狀態項

- 照「要不要讀者處理」分組。要處理的寫在 `.act`，明細寫在 `.items`。
- 不用處理的合成一節 `.groups`：每組一行，左邊組名，右邊內容。不逐項加狀態標記。
- `.st` 只用在表格的狀態欄；`.dot` 只用在狀態欄的表頭。表格下用 `.legend` 說明每個狀態詞。

### 版面

- 內容欄最寬 760px；內文每行最多 45 個中文字（`--measure: 45em`）。
- 區塊間距只用 `.page` 的 gap（40–52px）；元件不加外距。
- 表格：文字欄最多 3 欄；數字矩陣最多 7 欄（1 個文字欄＋6 個數字欄）。超過就拆表，或收進 `details.more`。
- 390 寬：頁面不水平捲動；3 欄文字表用 `.tbl.stack`，每列疊成一段；數字矩陣整張看得到，不捲動。
- 數字欄靠右；0 加 `.zero`；合計加 `.total`。
- 有文字標籤的 SVG 可以在 `.fig .scroll` 裡橫向捲動；長條圖這類能縮放的圖加 `.fit`。
- 可點的目標（`summary`、按鈕）至少 44px 高。
- 頁面專用的樣式超過 20 行：補進樣板，不留在單頁。
- 不用：emoji、裝飾插圖、漸層背景、陰影、卡片、彩色側邊線、標題上方的小標（eyebrow）、標題前的小方塊或圓點、方塊編號、`.st` 以外的標籤（badge、chip）。

## 從樣板起手

- 複製 `page.html`，刪掉用不到的區塊。HTML 註解寫了每個元件的用法。
- 本機檔用 `<link>` 引 `page.css`。發布成 artifact：`scripts/build_page.py` 內嵌 `page.css`，拿掉 `<!doctype>`、`<html>`、`<head>`、`<body>`。
- `page.css` 的 `shared:start`–`shared:end` 區塊跟 `architecture-site` 的 `shared.css` 相同；要改就兩邊一起改。
- 狀態用語照 [structure-rules.md](structure-rules.md)〈狀態用語〉定；每個值對一個 tone：`.st.ok`、`.st.warn`、`.st.bad`、`.st`（不確定、未開始）。
- 資料截至日期寫在 `.sub`。某一項的資料比較舊：在那一項後面用 `.meta` 寫「某天的狀態，之後沒有紀錄」。
- 沒有證據的結論：在 `.claim` 裡寫「（沒有證據）」，不加狀態標記。

## 視覺驗收

先跑 `scripts/check_page.py`（title、token、深色模式、外部資源、本機路徑、emoji、連結）。再截 4 張全頁圖：寬 1280 與 390，淺色與深色。開沒有 viewport meta 的 artifact 檔時，390 寬不開手機模擬，不然會用 980 寬排版。

```
視覺驗收：
- [ ] 1280×900 第一個視窗看得到結論、要做的事、風險
- [ ] h1 寫的是結論句，是整頁最大的字
- [ ] 要讀者做的事不讀文字也找得到：整頁的底色塊只有 .act 與建議的選項
- [ ] 框線只在表格與圖；沒有卡片、標籤、方塊編號、標題前的小方塊
- [ ] 狀態標記只在表格的狀態欄
- [ ] 390 寬沒有水平捲動（scrollWidth 等於 clientWidth）
- [ ] 390 寬表格讀得完：數字矩陣整張可見，文字表每列疊成一段
- [ ] 深色模式：文字都讀得到，底色塊看得出來，4 種狀態分得出來
- [ ] 中文是黑體（蘋方、思源黑體或微軟正黑體），不是新細明體或襯線字；程式碼是等寬字
- [ ] 收合區點得開、收得回
```

- 4 張截圖一起交給審查者，見 [review.md](review.md)。
