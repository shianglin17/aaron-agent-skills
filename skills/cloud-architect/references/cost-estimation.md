# 成本估算

eval 步驟 4 用。順序固定：使用量假設 → 單價 → 腳本計算 → 三情境 → 對照預算。

## 1. 使用量假設

每個計費維度都要有數字和出處（使用者給的、推算的、預設值）。

| 維度 | 低 | 可能 | 高 | 出處 |
|---|---|---|---|---|
| 每月請求數 | | | | |
| 平均回應大小（KB） | | | | |
| 對外流量（GB／月） | | | | |
| 運算時數或 vCPU‧秒 | | | | |
| 資料庫規格與儲存（GB） | | | | |
| 物件儲存（GB）與請求數 | | | | |
| 日誌量（GB／月） | | | | |
| 該雲特有的維度（見雲檔） | | | | |

- MAU 換算請求數要寫出換算方式，例如「每位 MAU 每月 20 次造訪 × 每次 30 個請求」，並標為假設。
- 三個情境只改使用量，不改架構。架構不同就是不同候選。

## 2. 單價

照 [verification.md](verification.md)。每個單價記：服務、計費單位、區域、方案、USD 單價、來源 URL、查詢日期。

## 3. 腳本

假設與單價放在腳本最上面，報告附完整腳本：

```python
PRICES = {"egress_gb": 0.0}  # 區域、USD、來源 URL、查詢日期寫在註解
SCENARIOS = {"低": {"egress_gb": 0}, "可能": {"egress_gb": 0}, "高": {"egress_gb": 0}}

for name, s in SCENARIOS.items():
    items = {"對外流量": s["egress_gb"] * PRICES["egress_gb"]}
    print(name, {k: round(v, 2) for k, v in items.items()}, "合計", round(sum(items.values()), 2))
```

- 月時數以價格頁寫的為準（常見 730）。
- 先列原價，再另算一行「扣除免費額度、credits、承諾折扣後」。

## 4. 常漏的費用

每個候選逐項檢查，不適用寫「不適用」：

- [ ] 對外流量：到網際網路、到 CDN、跨區域
- [ ] NAT：每小時費用加每 GB 處理費
- [ ] 跨可用區流量：多可用區部署、資料庫複本
- [ ] 負載平衡器：沒有流量也有每小時最低費用
- [ ] 公有 IP 位址
- [ ] 日誌與監控：寫入量、保存期、自訂指標
- [ ] 資料庫：高可用的加倍費用、備份儲存、快照
- [ ] 儲存：請求次數、取回費用、最短保存期
- [ ] 密鑰與憑證管理
- [ ] DNS 託管與查詢
- [ ] 容器映像儲存
- [ ] 寄信服務
- [ ] 技術支援方案
- [ ] 免費額度到期後的價格
- [ ] 該雲特有的項目（見雲檔〈計價注意事項〉）

## 5. 三情境與預算

金額來自腳本輸出：

| 項目 | 低 | 可能 | 高 |
|---|---|---|---|
| （逐項） | | | |
| 合計（USD／月） | | | |
| 對照預算上限 | 未超過／超過 | | |

- 「可能」超過預算：在結論明講，提出降本選項（降規格、改架構、承諾折扣）與各自的代價。
- 只有「高」超過：寫成風險，說明觸發條件，例如「月流量超過 ○○ GB」。
- 報告附一句「實際費用以帳單為準」，並附該雲的計算機連結。
