# 內容規則

寫任何文字、數字、程式碼位置時照這份。

## 放什麼

| 放 | 不放 |
|---|---|
| 現況：系統現在怎麼運作 | 走錯的路、遷移歷程、版本演變 |
| 結論：選了什麼、效果如何 | 統計細節（p 值、信賴區間） |
| 關鍵數字，附出處 | 決定編號、題號、內部代碼、ticket 編號 |
| 連到決策文件的連結 | 決策文件的內容本身 |

- 例外：一個「試過不行的」區塊，依影響排序，每項一句話加連結。
- 元件用白話名稱；英文產品名放副標。
- 現況與計畫分開寫。待決定、未實作的元件或功能加灰色標籤（`.tag.plan`）。

## 驗收

- 用「讀者能回答哪些問題」驗收，不用「全部涵蓋」。
- 每頁寫一句驗收句：「讀完這頁，讀者能回答＿＿」。
- 涵蓋檢查只確保重要結論沒漏：列出決策文件的結論，每條標出在哪一頁，或標「不放」。

## 字數預算

| 單位 | 上限 |
|---|---|
| 一個說明（面板的 `lede`、節點描述） | 3 句、約 120 字 |
| 一段或一個面板的數字 | 3 個 |
| header 的大數字 | 3–4 個 |
| 同一個數字 | 只放在最主要的那一頁；其他頁連過去 |

- 超過預算：把細節收進 `<details>`，或拆到下一層。
- 表格一律收進 `<details>`。

## 程式碼位置

- 寫成 `檔名:行號`，例如 `api/chat.py:42`。檔名用 repo 相對路徑。
- 頁尾寫「行號以 commit `<7 碼>` 為準」。全站用同一個 commit。
- 每次更新：換成新的 commit，重新核對每個行號。
- 程式裡的常數（門檻、上限、逾時）寫進面板時，同時記下常數名稱，讓檢查腳本比對。

## 數字

| 情況 | 寫法 |
|---|---|
| 量測或查詢來的數字 | 標查詢日期與出處（指令、查詢、報表） |
| 平均值 | 註明次數，例如「平均 1.2 秒（30 次）」 |
| 自編的範例值 | 標「示意」 |
| 沒量過 | 寫「沒有紀錄」；不要估 |
| 程式常數 | 跟程式比對；不一致以程式為準 |

- 首頁放「數字出處」表：數字、出處、查詢日期。收進 `<details>`。
- 日期用 `YYYY-MM-DD`。
