# 內容規則

寫任何文字、數字、程式碼位置時照這份。通用規則先照 `doc-types`，這裡只寫說明站專用的：

- `doc-types` 的 structure-rules.md：〈不放過程〉（含「試過不行的」例外）、〈一個事實只出現一次〉、〈篇幅〉、〈狀態用語〉。
- `doc-types` 的 SKILL.md 步驟 3：驗收題，不用「全部涵蓋」當驗收。
- `doc-types` 的 types.md〈解釋〉：每一頁的骨架。

## 放什麼

| 放 | 不放 |
|---|---|
| 現況：系統現在怎麼運作 | 遷移歷程、版本演變 |
| 結論：選了什麼、效果如何 | 統計細節（p 值、信賴區間） |
| 關鍵數字，附出處 | 決定編號、題號、內部代碼、ticket 編號 |
| 連到決策文件的連結 | 決策文件的內容本身 |

- 元件用白話名稱；英文產品名放副標。
- 待決定、未實作的元件或功能加灰色標籤（`.tag.plan`）。

## 驗收

- 每頁寫一句驗收句：「讀完這頁，讀者能回答＿＿」。它就是這一頁的驗收題。
- 涵蓋檢查只確保重要結論沒漏：列出決策文件的結論，每條標出在哪一頁，或標「不放」。
- 涵蓋檢查不是驗收：舊頁或決策文件的內容不用全部搬上來。

## 字數預算

| 單位 | 上限 |
|---|---|
| 一個說明（面板的 `lede`、節點描述） | 3 句、約 120 字 |
| 一段或一個面板的數字 | 3 個 |
| header 的大數字 | 3–4 個 |
| 同一個數字 | 只放在最主要的那一頁；其他頁連過去 |

- 超過預算：把細節收進 `<details>`，或拆到下一層。
- 表格一律收進 `<details>`；說明站以圖為主，表格是查證用的明細。

## 程式碼位置

- 寫成 `檔名:行號`，例如 `api/chat.py:42`。檔名用 repo 相對路徑。
- 頁尾寫「行號以 commit `<7 碼>` 為準」。全站用同一個 commit。
- 每次更新：換成新的 commit，重新核對每個行號。
- 程式裡的常數（門檻、上限、逾時）寫進面板時，同時記下常數名稱，讓檢查腳本比對。

## 數字

數字附出處與日期、沒量過寫「沒有紀錄」，照 `doc-types`。說明站另外：

| 情況 | 寫法 |
|---|---|
| 平均值 | 註明次數，例如「平均 1.2 秒（30 次）」 |
| 自編的範例值 | 標「示意」 |
| 程式常數 | 跟程式比對；不一致以程式為準 |

- 首頁放「數字出處」表：數字、出處、查詢日期。收進 `<details>`。
- 日期用 `YYYY-MM-DD`。
